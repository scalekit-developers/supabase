Let a team member connect to your project database as a [Postgres role](/docs/guides/database/postgres/roles), using their own [access token](/docs/guides/platform/personal-access-tokens) instead of a shared password. This follows security best practices, allowing each person to only access what they need for as long as they need it.

Use this guide when:

- Your team shares the `postgres` password, and you want each person to connect with their own credentials.
- Someone needs database access that [ends on a date you set](#restrict-a-team-members-access).
- You want to remove one person's access without changing a password everyone else uses.

For how temporary access works and how to connect with it, see [Temporary access](/docs/guides/platform/temporary-access).

A role mapping authorizes a team member to assume one or more Postgres roles. It creates no new role or user in the database, and the assumed role's permissions still apply. The role's own password keeps working, so long-lived service connections don't change.

## Prerequisites

Before you authorize a team member, set up the following:

- [Enable temporary access](/docs/guides/platform/temporary-access#manage-temporary-access-via-the-management-api) on the project.
- Create a [personal access token](/dashboard/account/tokens) to call the Management API. If you [scope the token](/docs/guides/platform/personal-access-tokens), give it **Organization Members** with **Read** access and **Database JIT** with **Read-write** access.

## Authorize a team member

To authorize a team member:

1. Set your access token, project ref, and organization slug:

   ```bash
   export SUPABASE_MANAGEMENT_API_TOKEN="your-access-token"
   export PROJECT_REF="your-project-ref"
   export ORG_SLUG="your-org-slug"
   ```

   The organization slug is the part of your organization's dashboard URL after `/org/`.

2. List the organization's members, and copy the `user_id` of the team member you want to authorize. The team member must have access to the project:

   ```bash
   curl "https://api.supabase.com/v1/organizations/$ORG_SLUG/members" \
     -H "Authorization: Bearer $SUPABASE_MANAGEMENT_API_TOKEN"
   ```

3. Map the team member to the roles they can assume. List every role the team member can assume in each request. This example authorizes the `postgres` role, which has broad privileges on your database. If the team member doesn't need them, map a narrower role. To restrict access from the start, add the restrictions from [Restrict a team member's access](#restrict-a-team-members-access) to this request:

   ```bash
   export MEMBER_USER_ID="the-member-user-id"

   curl -X PUT "https://api.supabase.com/v1/projects/$PROJECT_REF/database/jit" \
     -H "Authorization: Bearer $SUPABASE_MANAGEMENT_API_TOKEN" \
     -H "Content-Type: application/json" \
     -d @- <<EOF
   {
     "user_id": "$MEMBER_USER_ID",
     "roles": [{ "role": "postgres" }]
   }
   EOF
   ```

The team member can now connect as the `postgres` role, with their access token as the password. For connection strings, see [Using temporary access](/docs/guides/platform/temporary-access#using-temporary-access).

## Restrict a team member's access

Each role in the mapping takes two optional restrictions:

- `expires_at`: a Unix timestamp in seconds. After it passes, the database rejects the connection, even if the access token is still valid.
- `allowed_networks`: the CIDR ranges the team member can connect from. Put IPv4 ranges in `allowed_cidrs` and IPv6 ranges in `allowed_cidrs_v6`.

This example uses the variables from [Authorize a team member](#authorize-a-team-member). It limits the `postgres` role to one IPv4 address for seven days. Replace `176.1.12.1/32` with the address or range the team member connects from:

```bash
export EXPIRES_AT=$(( $(date +%s) + 7 * 24 * 60 * 60 ))

curl -X PUT "https://api.supabase.com/v1/projects/$PROJECT_REF/database/jit" \
  -H "Authorization: Bearer $SUPABASE_MANAGEMENT_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d @- <<EOF
{
  "user_id": "$MEMBER_USER_ID",
  "roles": [
    {
      "role": "postgres",
      "expires_at": $EXPIRES_AT,
      "allowed_networks": {
        "allowed_cidrs": [{ "cidr": "176.1.12.1/32" }]
      }
    }
  ]
}
EOF
```
